School Structure & Dual-School Architecture

Ammar Bin Yasir Institute operates two distinct schools under one organization. Some students attend both, creating a unique "Combined" enrollment pattern.

🕌 The Two Schools

School Schedule Focus Example Subjects
Tahfeez Morning Complete memorization & recitation of the Holy Qur'an Qur'an Hifz, Tajweed, Revision, Fluency
Islamiyya Evening Broad Islamic sciences + Western academic subjects Arabic, Fiqh, Mathematics, English, Science

📂 Section → Class Hierarchy

Each section contains both nursery-level and primary-level classes.

Section: Tahfeez ├── Raudah 1 (nursery) → class_type = 'nursery' ├── Raudah 2 (nursery) → class_type = 'nursery' ├── Halqa 1 (primary) → class_type = 'primary' └── Halqa 2 (primary) → class_type = 'primary' Section: Islamiyya ├── Raudah 1 (nursery) → class_type = 'nursery' ├── Raudah 2 (nursery) → class_type = 'nursery' ├── Class 1 (primary) → class_type = 'primary' └── Class 2 (primary) → class_type = 'primary' Section: Combined (attends BOTH morning & evening) ├── Raudah 1 (nursery) → subjects from Tahfeez + Islamiyya ├── Class 1 (primary) → subjects from Tahfeez + Islamiyya └── Class 2 (primary) → subjects from Tahfeez + Islamiyya

🔑 The Combined Student Solution

How we handle students who attend both schools without dual enrollment.

Core Principle: The "combining" happens at the subject level, not the enrollment level. Combined students have ONE enrollment, ONE student ID. Their class simply has subjects from both Tahfeez and Islamiyya assigned to it.

How it works:

  • Every subject has a school_type field: 'tahfeez' or 'islamiyya'
  • Pure Tahfeez class → only Tahfeez-tagged subjects assigned via class_subjects
  • Pure Islamiyya class → only Islamiyya-tagged subjects assigned
  • Combined class → subjects from both are assigned
  • Report card groups subjects by school_type and shows a combined average

👩‍🏫 Teachers Across Schools

A teacher can teach at both schools. The system handles this via subject-level assignments.

TablePurposeExample
teacher_class_assignments Administrative class teacher role (attendance, remarks) Mallam Ibrahim is class teacher of Class 1 (Islamiyya)
teacher_subject_assignments Teaching role: which subject in which class Mallam Ibrahim teaches Qur'an in Class 1 (Islamiyya) AND Tajweed in Raudah 2 (Tahfeez)
No conflict: A teacher with rows in teacher_subject_assignments pointing to different classes across Tahfeez and Islamiyya sections works seamlessly. Each row is a unique (teacher, class, subject, session) tuple.

Section 03

Flow 1 — Academic Setup

One-time setup per academic year by the administrator. Must be done before anything else.

1
Create Academic Session Done
Navigate to Settings → Sessions. Create session (e.g., "2025/2026") with start/end dates. Mark as active.
  • UI: /settings → Sessions tab
  • Table: sessions
2
Create Terms Done
Under the session, create 3 terms (1st, 2nd, 3rd) with their date ranges. Mark the current term as active.
  • UI: /settings → Terms tab
  • Table: terms
3
Create Sections Done
Create sections: Tahfeez, Islamiyya, Combined. These are the organizational groupings, not the class level.
  • UI: /classes → Add Section
  • Table: sections
4
Create Classes Done
Create classes under each section (Raudah 1, Class 1, Halqa 1, etc.). Set class_type (nursery/primary) and optionally assign a class teacher.
  • UI: /classes → Add Class
  • Table: classes
5
Create Subjects Done
Create all subjects with their school_type tag (tahfeez or islamiyya).
  • UI: /settings → Subjects (or via class detail page)
  • Table: subjects
6
Assign Subjects to Classes Done
For each class, select which subjects it offers. Combined classes get subjects from both school types.
  • UI: /classes/[id] → Subjects tab
  • Table: class_subjects
7
Set Up Grading Scheme Done
Define grade boundaries: A+ (≥90), A (80-89), B+ (70-79), B (60-69), C (50-59), D (40-49), F (<40).
  • UI: /settings → Grading tab
  • Table: grading_schemes

Section 06

Flow 4 — Score Entry & Draft Management

How teachers and admins enter assessment scores with offline draft support.

1
Navigate to Score Entry Done
  • Admin: /assessments/results/finalize → Select class
  • Teacher: /teacher/results → Auto-selects their assigned class
  • Session and term auto-selected from active period
2
Select Subject (Subject View) Done
Choose a subject from the class's assigned subjects. The system loads all enrolled students and their existing scores in an editable spreadsheet.
  • Columns: Student Name, CA1 (20), CA2 (20), Exam (60), Total (100), Grade, Remarks
  • Total, Grade, and Remarks auto-calculate as scores are entered
3
Enter Scores Done
Click "Edit Scores" to enter edit mode. Type CA1, CA2, and Exam scores for each student. Tab between fields.
  • Score validation: CA1/CA2 max 20, Exam max 60
  • Total = CA1 + CA2 + Exam (auto-calculated)
  • Grade and Remarks auto-populate based on grading scheme
4
Draft Management Done
Unsaved changes are automatically cached in localStorage as drafts.
  • Auto-save: Changes are cached every few seconds
  • Draft detection: On page load, if a draft exists, user is prompted to restore or discard
  • Draft preview: Shows a diff table of all changed scores (old → new)
  • Save as Draft: Intentionally save to continue later
  • Multi-subject drafts: Each subject's draft has its own restore/save buttons
  • Saving scores to the database always clears the draft with confirmation
5
Save Scores Done
Click "Save Scores" to persist all changes to the database.
  • Creates/updates assessments rows (one per assessment type per subject per class per term)
  • Creates/updates student_scores rows (one per student per assessment)
  • Clears the local draft on successful save

Section 07

Flow 5 — Result Processing & Finalization

After all scores are entered, results are generated, positions calculated, and remarks added.

1
Generate Class Results Done
Admin clicks "Generate Results" which aggregates all subject scores into student totals and calculates class positions.
  • Sums all subject totals per student
  • Calculates average score
  • Ranks students by average (position 1, 2, 3...)
  • Preserves existing teacher/principal remarks and attendance data
  • Uses upsert to avoid data loss on re-generation
  • Table: student_results
2
Enter Attendance Data Done
Enter total school days in term and days present for each student.
  • Fields: total_school_days, attendance_present
  • Days absent = total_school_days - attendance_present (auto-calculated)
3
Enter Teacher Remarks Done
Class teacher writes personalized remarks for each student.
  • Field: teacher_remark on student_results
4
Enter Principal Remarks Done
Head teacher / principal writes remarks for each student.
  • Field: principal_remark on student_results
5
Rate Affective & Psychomotor Skills Done
Rate each student on behavioral and motor skills (1-5 scale).
  • Affective: Punctuality, Politeness, Neatness, Honesty, Leadership, Cooperation, Attentiveness, Perseverance, Attitude to work
  • Psychomotor: Handwriting, Verbal fluency, Sports, Handling tools, Drawing & painting
  • Table: student_skills

Flow 7 — Cumulative (Combined Term) Results

How 2nd and 3rd term report cards show previous term scores alongside current scores.

🧮 How Cumulative Scores Work

No new database tables needed. Data is queried from existing student_scores at render time.

Key Principle: Previous term scores are fetched on-the-fly when generating the report card. If a teacher corrects a 1st term score, the cumulative averages automatically update — no sync issues.
Term Being PrintedColumns ShownCumulative Calculation
1st Term CA1, CA2, Exam, Total, Grade No cumulative — just the current term
2nd Term 1st Term Total, CA1, CA2, Exam, Total, Grade, Cum. Avg (1st + 2nd) ÷ 2
3rd Term 1st Term Total, 2nd Term Total, CA1, CA2, Exam, Total, Grade, Cum. Avg (1st + 2nd + 3rd) ÷ 3

Avg │ ├────────────┼──────────┼──────────┼─────┼─────┼──────┼───────┼───────┼──────────┤ │ Mathematics│ 78 │ 82 │ 17 │ 18 │ 50 │ 85 │ A+ │ 81.7 │ │ English │ 65 │ 70 │ 14 │ 14 │ 44 │ 72 │ B+ │ 69.0 │ │ Arabic │ 72 │ 75 │ 15 │ 16 │ 48 │ 79 │ B+ │ 75.3 │ │ Fiqh │ 68 │ 66 │ 13 │ 14 │ 43 │ 70 │ B │ 68.0 │ └────────────┴──────────┴──────────┴─────┴─────┴──────┴───────┴───────┴──────────┘

The query:

SELECT a.term_id, a.subject_id, s.name, SUM(ss.score) as term_total
FROM student_scores ss
JOIN assessments a ON ss.assessment_id = a.id
JOIN subjects s ON a.subject_id = s.id
WHERE ss.student_id = <student_id>
  AND a.session_id = <session_id>
  AND a.class_id = <class_id>
  AND a.term_id IN (<term1_id>, <term2_id>, <term3_id>)
GROUP BY a.term_id, a.subject_id, s.name;

Flow 8 — End of Year: Student Promotion

At the end of 3rd term, promote students to the next class for the new academic session.

1
Create New Session Done
Create the next academic session (e.g., "2026/2027") and its 3 terms.
2
Bulk Promotion UI Not Started
A dedicated UI where admin can:
  • See all students grouped by current class
  • Select target class for promotion (e.g., Raudah 1 → Raudah 2)
  • Mark individual students for: Promote, Repeat, or Graduate
  • Bulk promote all selected students to the new session
  • Creates new student_enrollments rows for the new session
3

  • Repeaters: Re-enroll in the same class for the new session
  • Transfers: Students leaving the school — mark enrollment as inactive
  • New admissions: Students joining mid-session — register normally
